La Vista de Desarrollo describe cómo se organiza el código fuente. SIGA utiliza un **Monorepo** para garantizar la integridad de los contratos entre el front y el back.

## 2. Componentes y Capas Técnicas

| Componente | Rol en el Ecosistema | Stack Principal |
| :--- | :--- | :--- |
| **Backends** | Microservicios transaccionales e IA. | Kotlin (Spring) / Python (FastAPI) |
| **Frontends** | Interfaces de usuario responsivas. | SvelteKit / Tailwind CSS |
| **Common** | Contratos y utilidades compartidas. | JARs compartidos / TS Definitions |

## 🛡️ Defensa del Arquitecto (Tips para tu Capstone)

> **¿Por qué incluimos las Webs de Marketing en el Repo?**
> "Un producto SaaS como SIGA no es solo el Dashboard. Al incluir la **Web Comercial** y la **Landing** en el Monorepo, aseguramos que cualquier cambio en la marca o en los planes de precios se refleje de forma atómica en todo el ecosistema, manteniendo la coherencia visual y de negocio".
>
> **¿Es la WebApp un microservicio?**
> "Técnicamente, es un artefacto de frontend, pero en nuestra arquitectura la tratamos con la misma rigurosidad que un microservicio: tiene su propio Dockerfile, su propio pipeline de despliegue y consume contratos versionados del backend".
